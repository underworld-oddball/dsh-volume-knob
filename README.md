# dsh-volume-knob

> 朗读 + 音量，一个按钮。从**你最新那条提问的开头**朗读，或按住按钮在页面上**任选一个起点**。
> Read aloud from the start of your newest question — or from any spot you pick. One button.

[![npm version](https://img.shields.io/npm/v/dsh-volume-knob.svg)](https://www.npmjs.com/package/dsh-volume-knob)
[![license](https://img.shields.io/npm/l/dsh-volume-knob.svg)](LICENSE)

DeepSeek Harness（DSH）Web GUI 的输入框工具行里、**模型选择框左边**的一个扬声器按钮：

- **单击**：从朗读起点开始朗读，页面自动翻到起点并闪烁一根光标；**再单击停止**。
- **按住约 0.4 秒后松手**：进入「挑选起点」状态，在页面上单击任意可朗读文字，从那里开始朗读。
- **按住并向上拖拽**：打开**竖式音量混音台**，分别调节**页内媒体音量**与**系统输出音量**。
- 朗读时图标变为主题色并多一道声波弧；挑选起点时光标为琥珀色。

作者 / by **江湖老妖**。

> 适用：DSH Web GUI（`dsh web`）。系统音量目前支持 macOS 与 Linux。

## 功能特性

- **一键朗读**：从最新提问的第一个字读到最新回复结尾，自动滚动到起点。
- **任意起点**：按住按钮松手后，在页面上单击想开始读的位置即可；代码块、表格都能作为起点。
- **精确到字**：光标、滚动定位和左右键微调都基于真实的字符 → DOM 映射，而不是 CSS 估算。
- **优先 dsh-tts**：装了 [dsh-tts](https://github.com/GooDAnDREaDY/dsh-tts) 就用它配置的音色；没装或合成失败时自动回退浏览器语音。
- **两个音量**：页内媒体音量（本标签页所有 `<audio>`/`<video>`）与系统输出音量，各自可静音。
- **双语提示**：悬停气泡与挑选提示都是中文在上、灰色英文在下。
- **无构建步骤**：浏览器半不需要打包，直接由 DSH 的模块加载器加载，测试也直接跑这份代码。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| DSH | `>= 0.1.5-rc.3`（见 `package.json` 的 `engines.dsh`），Web GUI |
| 浏览器 | 能运行 DSH Web GUI 的现代浏览器 |
| 系统音量 | macOS（内置 `osascript`）或 Linux（`pactl`，pulseaudio / pipewire-pulse） |
| 可选 | [dsh-tts](https://github.com/GooDAnDREaDY/dsh-tts)；不装也能用浏览器语音 |

## 安装

### 从 npm 安装（推荐）

```sh
dsh plugin --profile web add dsh-volume-knob
```

### 从 GitHub 安装

相当于直接取仓库源码，未发 npm 或想跟最新提交时可用：

```sh
dsh plugin --profile web add github:underworld-oddball/dsh-volume-knob
```

### 从插件市场安装

插件收录进社区目录后，也可以在 **设置 → 插件市场**（`dsh-market`）里搜索 `dsh-volume-knob` 一键安装。

### 安装后

1. **重启 `dsh web`**（插件在启动时织入 boot graph）。
2. **刷新页面**。
3. 输入框工具行里、模型选择框左边会出现扬声器按钮。

按钮注册在 `conversation.input.right` 槽位，并显式设了 `order: 40`。同一槽位有多个插件时先比 `priority`、再比 `order`，所以它固定贴着模型选择框的左侧。

### 更新与卸载

```sh
# 更新：重新执行 add，pnpm 会解析到 npm 上的最新版
dsh plugin --profile web add dsh-volume-knob

# 卸载
dsh plugin --profile web remove dsh-volume-knob
```

更新或卸载后同样需要**重启 `dsh web` 并刷新页面**。

## 使用说明

### 手势总览

| 手势 | 行为 |
| --- | --- |
| 单击图标 | **按下**收起悬浮提示 → **松手**开始朗读（滚动到起点、闪烁光标）；再单击停止 |
| 按住 ≥400ms → 松手 | 进入挑起点状态：图标上方提示变为「选择开始位置后点击 / After Pick → Tap」 |
| 挑起点时移动鼠标 | 提示词消失，挑选继续；十字光标保持 |
| 挑起点时单击可朗读文字 | 光标落在该字上，**立刻从那里开始朗读** |
| 挑起点时单击空白处 | 取消本次挑选 |
| 挑起点时按任意键 / 滚轮 / 拖动 / 右键 / 窗口失焦 | 取消本次挑选 |
| 挑起点时一直不动 ≥5 秒 | 自动取消本次挑选（每次移动鼠标重新计时） |
| 按住并向上拖拽 ≥18px | 打开音量混音台（从图标上方弹出） |
| 混音台打开时单击图标 | 只收起混音台 |
| 点击页面其他地方 / `Esc` | 收起混音台 / 取消挑选 |
| 朗读自然结束 | 光标彻底消失，起点回到默认 |

### 单击：朗读 / 停止

没有保存过起点时，单击从**默认起点**（最新提问的第一个字）读到**最新回复的结尾**。朗读期间：

- 页面会滚动到起点，并在起点显示一根**闪烁的光标**（主题色）。
- 图标变为主题色，并多一道声波弧。
- 再单击一次停止；自然读完也会停止。
- 停止或读完后，光标彻底消失，不会残留，也不会选中文字、影响复制。

### 按住：选择起点

1. 按住图标约 **0.4 秒**（按住期间提示词保持不变）。
2. **松手**后，图标上方出现「选择开始位置后点击 / After Pick → Tap」。
3. **移动鼠标**，提示词消失，但挑选状态保持，页面保持十字光标。
4. 在想开始读的位置**单击**：光标落下，并立刻从那里朗读。

挑选期间如果**一直不动超过 5 秒**，会自动取消；按任意键、滚轮、拖动、右键、点空白或切走窗口也会取消。取消后提示词与光标一起收起，想重来把鼠标移回图标再长按一次。

> 提示词在松手后才变化、移动鼠标后才消失：这样「按钮上方的提示」不会挡住你要点击的正文。

### 按住上滑：音量混音台

按住图标向上拖动超过 **18px** 即打开混音台，松开鼠标不会触发朗读。

混音台有两列竖式推子：

| 推子 | 管什么 | 不管什么 |
| --- | --- | --- |
| **页内音量** | 本标签页里所有 `<audio>`/`<video>` 的 `volume`：语音朗读、提示音、网页播放器 | 系统音量、其他 App、其他标签页 |
| **系统音量** | 系统输出音量与静音（macOS `osascript`，Linux `pactl`） | 单个页面元素的音量上限 |

两者是串联关系：系统音量是天花板。系统静音时页内开满也没声；页内拉到 0 只静这一页。页内音量与静音状态会保存在 `localStorage`，刷新后仍在。

混音台打开时，点击页面其他地方或按 `Esc` 可收起；单击图标只收起混音台，不会开始朗读。

### 键盘操作

按钮聚焦时：

| 按键 | 行为 |
| --- | --- |
| `Enter` / `Space` | 开始朗读 / 停止朗读 |
| `Alt` + `↑` | 打开 / 收起混音台 |
| `←` / `→` | 移动当前朗读标记 1 个字符（需先有标记） |
| `Shift` + `←` / `→` | 移动当前朗读标记 20 个字符 |

> 挑选起点期间按任意键都会取消挑选，所以左右键微调要在正常朗读/标记存在时使用。

按钮带有 `aria-label`、`aria-pressed` 和 `aria-expanded`，读屏软件可以识别状态。

### 图标与提示状态

- **空闲**：灰色扬声器；悬停显示三列双语提示（点击朗读 / 长按选起点 / 上滑调音量）。
- **朗读中**：主题色扬声器 + 额外声波弧；悬停显示「点击停止 / Tap: Stop」。
- **挑选中**：光标变为琥珀色，页面保持十字光标；图标上方显示「选择开始位置后点击」。
- **系统音量不可用**：混音台对应一列置灰并显示「不可用」，把鼠标停在上面可看到具体原因。

## 朗读起点与光标

- **默认起点**：你**最新那条提问**的第一个字。第一次使用、刚停止或读完之后，单击或按 `Enter` 都从这里读到最新回复结尾。
- **自定义起点**：按住约 0.4 秒后松手，再在页面上单击想开始读的位置。选中的是真实字符位置，光标与朗读都从那个字开始。
- **按会话保存**：起点以 `{段落 key, 字符偏移}` 记录在 `localStorage`。刷新页面后，如果对应的段落仍在，会恢复该起点，下一次单击从保存的位置开始；如果那段文字被重新渲染或已经不存在，自动回退到最新提问开头。
- **停止后归位**：朗读自然结束、手动停止或取消挑选都会清除当前页面里的标记；下一次单击回到默认起点（最新提问开头）。
- **光标只是标记**：它不选中文字、不影响复制，只在朗读或挑选期间出现。
- **流式回复**：回复仍在输出时，节点文字变化会按同一段落重新定位；整个节点被替换时回退到默认起点。

朗读的文本范围是从起点字符开始，沿「可朗读节点」一直读到末尾；更早的轮次不会自动朗读，但按住挑起点时可以选择更早的位置。

## 常见问题（FAQ）

### 1. 安装后按钮没有出现？

- 确认 DSH 版本满足 `>= 0.1.5-rc.3`，且使用的是 **Web GUI**。
- **重启 `dsh web`** 后再刷新页面；只刷新页面不会加载新插件。
- 检查安装是否成功：`dsh plugin --profile web why dsh-volume-knob`。
- 如果界面没有 `conversation.input.right` 这个槽位（版本过旧），插件会静默不挂载，按钮就不会出现。

### 2. 单击后没有声音？

按顺序检查：

1. **页内音量**：打开混音台，确认「页内音量」不是 0，也没有按「已静音」。
2. **系统音量**：确认系统输出没有静音，输出设备正确。
3. **朗读状态**：按钮变蓝说明正在朗读；如果立刻变回灰色，可能是没有可读内容或语音合成失败。
4. **浏览器语音**：没装 dsh-tts 时使用浏览器/系统的 `speechSynthesis`。如果系统没有可用语音或浏览器禁止自动播放，可能没有声音。
5. 打开诊断接口（见下节）查看最近事件，例如 `play:blocked`、`synth:http`、`read:browser-fallback`。

### 3. 提示「页面上没有可朗读的内容」？

说明当前会话里没有可朗读的节点。插件只读取 `data-chat-flow-kind` 为 `user` 或 `assistant-step`（且不是 `reasoning`）且实际可见的节点。空会话、所有内容都被隐藏，或 DSH 版本的消息 DOM 结构变化时会出现这个提示。

### 4. 系统音量显示「不可用」/ 推子灰掉？

- 系统音量只支持 **macOS** 和 **Linux**。其他平台该列会置灰并显示原因（把鼠标停在「不可用」上可看 tooltip）。
- Linux 需要 `pactl`。先确认命令存在并可用：

  ```sh
  pactl get-sink-volume @DEFAULT_SINK@
  pactl get-sink-mute @DEFAULT_SINK@
  ```

- macOS 使用内置的 `osascript`，一般无需额外安装。若命令被安全策略拦截，tooltip 会显示具体报错。

### 5. 没有安装 dsh-tts 能用吗？

可以。插件会先探测 `/dsh-tts/status`（一次/每页）；不可用时直接用浏览器 `speechSynthesis`，并把语言设为 `zh-CN`。装了 dsh-tts 则使用它配置的 provider/音色；某个分块合成失败时，剩下的部分会回退浏览器语音，不会从头重念。

### 6. 为什么思考过程、工具调用和「用量」不朗读？

这是**白名单**设计：只读 `user` 和 `assistant-step` 的 `response` 部分。`reasoning`（模型草稿）、`turn-process`（已完成工作）、`turn-tail`（用量/耗时）和 `tool-call`（工具卡片）都不属于要朗读的回复正文。

即使某个节点里混入了时间、token 数或「复制 / 重试」这类装饰行，也会在朗读前按行过滤掉。

### 7. 代码块和表格会被读吗？

会。正文里的代码、表格单元格都是普通文本节点，会按页面顺序朗读；按钮文字（复制、重试等）和界面装饰会被跳过。代码中的符号可能被语音引擎读得比较生硬，这属于语音引擎的行为。

### 8. 为什么朗读没有从我以为的位置开始？

- 第一次使用、刚停止或读完之后，直接单击或按 `Enter` 从**最新提问的第一个字**开始。
- 如果刷新过页面，且之前保存的起点仍能对应到同一段文字，会从那个保存的位置开始；否则回退到最新提问开头。
- 想换位置，必须**按住约 0.4 秒再松手**，等提示出现后**在正文上单击**；点空白处会取消。左右键只微调当前标记，不是设置新起点的入口。

### 9. 光标/提示为什么会自己消失？

- 朗读自然结束、手动停止或取消挑选后，光标会彻底消失，这是设计行为，不是故障。
- 挑起点时如果 5 秒没有任何动作，会自动取消；移动鼠标会重新计时。
- 挑选时按任意键、滚轮、拖动、右键或窗口失焦都会取消本次挑选。

### 10. 音量推子会影响别的插件或别的标签页吗？

- **页内音量**影响本标签页里所有 `<audio>`/`<video>`，包括 dsh-tts 的自动朗读和其他插件的提示音；不影响其他标签页。
- **系统音量**改的是操作系统输出音量，会影响其他 App。
- 点朗读按钮前会先暂停页面上正在播放的音频，所以不会和 dsh-tts 的自动朗读叠在一起。

### 11. 会把页面文字发到网上吗？

- 插件把文字发给**本机的 dsh-tts 路由** `/dsh-tts/speak`；dsh-tts 是否会再调用云端 provider，由它自己的配置决定。
- 没装 dsh-tts 时使用浏览器语音，具体由浏览器/系统实现。
- 系统音量通过本机命令修改；插件没有其他外部网络请求。写入类宿主路由只接受回环地址或同源请求。

### 12. 支持哪些 DSH 版本和系统？

- DSH `>= 0.1.5-rc.3`，仅 Web GUI。
- 槽位接口与消息 DOM 已在 DSH `latest`（0.1.5-rc.3）和 `next`（0.1.7-rc.1）上核对过。
- 系统音量：macOS、Linux；其他平台置灰。

### 13. 如何更新或卸载？

见「安装」一节的「更新与卸载」。更新或卸载后都要重启 `dsh web` 并刷新页面。

### 14. 朗读中途页面更新/重新渲染会怎样？

插件按「段落 key + 字符偏移」定位起点。文字在同一个节点内变化时会重新夹取到有效位置；整个节点被替换或文字对不上时，回退到最新提问开头。流式输出末尾偶尔会有轻微跳动，属于这个定位策略的边界。

## 诊断与排障

插件会把关键事件上报给宿主半，宿主保留最近 **60 条**。在同一 DSH Web 服务上访问：

```text
http://127.0.0.1:<你的 dsh web 端口>/dsh-volume-knob/diag
```

例如当前机器的 DSH Web 端口是 `3082`：

```sh
curl http://127.0.0.1:3082/dsh-volume-knob/diag   # 端口换成你的实际端口
```

常见事件：

| 事件 | 含义 |
| --- | --- |
| `apply` | 插件已加载，detail 是版本号 |
| `toggle` | 单击触发的开始/停止 |
| `read:start` / `read:chunks` | 朗读起点、文本长度、分块数 |
| `tts:absent` / `tts:probe-failed` | 没有检测到 dsh-tts |
| `synth:http` / `synth:throw` / `synth:empty` | dsh-tts 合成失败 |
| `play:ok` / `play:blocked` | 音频开始播放 / 被浏览器拦截 |
| `read:browser-fallback` | 回退到浏览器语音 |
| `gesture:*` / `click` | 长按、挑选、取消、普通点击 |

事件只包含状态与错误信息，不记录朗读正文。

## 工作原理

- **宿主半** `lib/index.js`：注册 `/dsh-volume-knob/system`（读取/写入系统音量）与 `/dsh-volume-knob/diag`（诊断）。macOS 用 `osascript`，Linux 用 `pactl`。
- **浏览器半** `lib/client.js`：在 `conversation.input.right` 槽位注册按钮，负责文本提取、字符定位、光标、朗读和混音台。
- **文本白名单**：真实 DSH DOM 中每个消息节点带 `data-chat-flow-kind`。只读 `user` 和 `assistant-step` 的 `response`；`reasoning`、`turn-process`、`turn-tail`、`tool-call` 都跳过。
- **字符映射**：按 `innerText` 语义把节点打平成文本串，同时记录「第 n 个字落在哪个文本节点的第几个字符」，所以光标、滚动和左右键都精确到字。
- **语音合成**：按约 220 字切句块，逐块 `POST /dsh-tts/speak`（带 `channel: 'web'`），顺序播放；失败时回退浏览器 `speechSynthesis`。
- **页内音量**：对 `HTMLMediaElement.prototype.play` 打一次补丁，覆盖所有播放中的元素，包括未挂到 DOM 的 `new Audio()`（dsh-tts 用的就是这种）。

## 兼容性

`engines.dsh` 使用下限 `>= 0.1.5-rc.3`，而不是按「最新版」收窄的范围：DSH 的 `latest`（0.1.5-rc.3）比 `next`（0.1.7-rc.1）旧，写死更高的下限会把 `latest` 挡在外面。

插件代码本身没有按 DSH 版本分支。但消息 DOM 的取值必须实测：当前白名单是在真实页面上核对过的 `user` / `assistant-step` / `reasoning` / `turn-process` / `turn-tail` / `tool-call`，不要只看接口名。
